# ENSv2 member rights: conservative snapshot probe

The read-only `scripts/probe-ensv2-member-autonomy.mjs` returns `UNPROVEN` in all cases. It accepts an externally pinned registry, label, expected holder/resolver and a numbered L1 Sepolia block. Its ABI subset follows the [official Permissioned Registry](https://docs.ens.domains/ensv2/permissioned-registry/) and [Permissioned Resolver](https://docs.ens.domains/ensv2/permissioned-resolver/) descriptions. Automated mutations test a transferred owner, expired or re-registered name, resolver change, root EAC administrative/regular rewrite rights, wrong network, code absence and failed reads.

The probe **cannot** independently prove member exclusivity: it does not pin proxy implementations, establish the parent chain, enumerate approvals, inspect resolver EAC roles/records, prove finality, or exclude future re-registration and migration. In particular, `ROLE_SET_RESOLVER`, `ROLE_SET_SUBREGISTRY`, `ROLE_UNREGISTER`, their root administrators and `ROLE_UPGRADE` may defeat member control. Even if `isEmancipated()` says true, the complete hierarchy and code identity need external corroboration. `safeTransferFrom` and `unsafeTransfer` have different ENSv2 constraints; transfer alone is no certificate of irrevocable rights. No ENSv1 NameWrapper fuse can substitute for this ENSv2 proof. G2.4 remains PENDING.
