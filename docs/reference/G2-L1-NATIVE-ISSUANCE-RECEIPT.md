# G2.4 — Historical native issuance receipt observation for OP preparation

**Status: read-only, legacy ENSv1 Sepolia, finalized-RPC observation only.** This does not submit an OP transaction, relay an authenticated cross-domain message, create a native ENS title certificate or close [G2.4](../goal/G2-ACCEPTANCE.md). It is a small follow-up to the [local L1 native atomic issuance proof](G2-L1-NATIVE-ATOMIC-ISSUE-PROOF.md), distinct from the [L1 finalized Monitor](G2-ZK-MERKLE-L1-AUTHORITY-DECISION.md).

The exported `observeNativeIssueReceipt({ client, profile })` function in `scripts/observe-g2-native-issuance-receipt.mjs` accepts a caller-verified JSON-compatible profile with exactly `chainId` (11155111), `issuer`, `issuerCodeHash`, `registryCodeHash`, `wrapperCodeHash`, `parentName`, `childLabel`, `member`, `expiry` (decimal string) and `transactionHash`. Its caller is responsible for independently pinning the **real deployment addresses, exact runtime code hashes, intended operation and native holder consent**. This prototype's issuer is only the local contract from PR #151; it is not claimed to exist on Sepolia.

Using viem's **read-only public client**, the function:

1. Rejects wrong chain, malformed names and labels, zero member, invalid hashes and unsafe source parameters before reading.
2. Reads an RPC's `finalized` L1 head, the *successful* native issuance receipt and the numbered block containing that transaction; verifies the receipt block hash and that the transaction hash is in the returned block.
3. Pins issuer, legacy ENSv1 Registry and NameWrapper bytecode at the **issuance transaction's block**, and reads the issuer's `parentNode`, `ENS_REGISTRY` and `NAME_WRAPPER` getters there. All must match the expected profile and official versioned ENSv1 contract addresses.
4. Decodes exactly one correctly bound `NativeChildIssued(node, member, expiry)` event from that issuer and receipt. The node is independently calculated from the requested lowercase ASCII label and parent namehash. Duplicate, missing or mismatched events fail closed.
5. Reads the Registry holder and NameWrapper `getData`/`ownerOf` at the receipt block's **end-of-block state** and requires member ownership, both CU/PCC fuses, exact expiry and Wrapper registry custody. This is not the transaction's intermediate post-instruction state: another transaction in that same block could change it, causing a conservative mismatch. Rechecks the finalized RPC head and receipt block hash before returning.

The result reports `historicalIssuanceObserved: true`, along with the receipt block/transaction/log identity; **always** reports `requestNonceVerified:false`, `opMirrorVerified:false`, `nativeCurrentAuthorityVerified:false`, `sovereignReceipt:false`, `enablesNativeIssuance:false` and evidence level `FINALIZED_RPC_OBSERVATION_ONLY`.

**Security boundaries:** The `finalized` tag, transaction receipt, block transactions and state reads all come from an RPC provider, **not an independently verified Ethereum consensus proof**. Even a genuine historical issuance receipt cannot show that the parent or child owner still holds rights after that block, or that L2 received the outcome. This contract event contains no OP request nonce, OP destination, request identifier or delivery sequence, so it **cannot cryptographically bind a queued L2 request** or enforce replay-safe authenticated OP mirroring. That requires a separately reviewed L1 emitter/message format with an explicit operation ID and a canonical L1→OP delivery verifier, or an independently verified equivalent proof. Changes after the issuing block must be reconciled by the source-specific ENS Monitor. Legacy ENSv1 logic cannot authorize current ENSv2 EAC operations.

This phase intentionally has no CLI, background worker, persistent cursor or live-chain action. Unit tests provide a mocked viem public client and adversarial receipt/issuer/state fixtures. Use this as **evidence preparation only** for a future native L1 outcome → OP authenticated message design, never as a direct grant gate.
