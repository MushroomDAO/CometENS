# G2.4 — bounded native-L1 result / OP mirror recovery observation

**READ-ONLY, local fixture only, G2.4 `PENDING`.** `auditNativeMirrorRecovery({l1Client,opClient,profile})` in `scripts/audit-g2-native-mirror-recovery.mjs` diagnoses the status of ONE independently pinned `issueAndRelay` result. It does **not** replay a message, grant OP/native rights, write either chain, prove consensus, certify *current* ENS ownership or emit `SOVEREIGN`.

Provide two archive-capable read-only clients (L1 Sepolia `11155111`, OP Sepolia `11155420`); profile uses all fields of [native receipt observation](G2-L1-NATIVE-ISSUANCE-RECEIPT.md) plus `opInbox`, `opInboxCodeHash`, `opRequester`, `requestNonce`, `l1Messenger`, `l1MessengerCodeHash` as independently verified pins (the existing reconciliation profile **minus** `opTransactionHash`, since a successful OP receipt need not exist yet). This is a library function with no key or RPC URL handling; profile and both clients are required. One request is examined per call; no unbounded indexer, scheduler or bulk RPC enumeration.

The L1 leg reuses the reviewed, finalized native issuance observer. It additionally checks the real `issueAndRelay` transaction calldata, result request ID/domain binding, the L1 issuer's bound OP inbox and Messenger/runtime pin, `sentRequest(requestId)` and **exactly one** matching `NativeIssueResultSent` event in its successful native L1 receipt. A failed `sendMessage()` in `issueAndRelay` atomically reverts L1 native issuance: absent/reverted receipts therefore **fail closed**; never label such a case an issued name with a lost message. A successful L1 transaction does **not** prove that the canonical messenger has already delivered its message to OP.

The OP leg samples the inbox runtime codehash, `parentNode`, `l1ResultEmitter` and **exact** `requests(requestId)` in ONE RPC-reported finalized OP block. It rechecks both chain IDs, finalized heads and the historical L1 source block hash before returning. Status `NONE` is accepted only with a genuinely empty Solidity request struct; `PENDING` and `CANCELLED` require the precise requester/node/member/expiry/nonce and zero source block; `OBSERVED` additionally requires its source block equal the finalized L1 result block. Any missing pin, unfinalized source, changed hash, forged request, unknown enum, wrong chain or source result fails closed.

| OP finalized snapshot | Audit classification | Conservative action |
| --- | --- | --- |
| `NONE` / unqueued | `OP_REQUEST_NOT_QUEUED` | L1 operation is not undone; inspect original OP queue and source ID |
| `PENDING`, unexpired at sampled OP block | `OP_PENDING_DELIVERY_UNKNOWN` | Inspect canonical messenger failure/replay status and downstream backlog independently |
| `PENDING`, native expiry already passed | `OP_PENDING_NATIVE_EXPIRED` | No live rights; historical delivery might still be observed |
| `CANCELLED` | `OP_CANCELLED` | Do not retry blindly; cancelled OP request rejects new observation |
| `OBSERVED` | `OP_PROVISIONALLY_OBSERVED` | Avoid duplicate delivery; use [finalized OP receipt reconciliation](G2-NATIVE-CROSSCHAIN-RESULT-RECONCILE.md) before claiming historical OP delivery |

**Idempotency is checked by state inspection, never enforced by this script.** The onchain OP inbox only accepts `PENDING → OBSERVED` once; duplicate `observeResult` calls revert. The audit cannot prove any particular unobserved message was lost, that a failed relay is safe to replay, the L1 result is currently valid, or that no source reorg occurred at a colluding RPC provider. A delayed result can set `OBSERVED` *after native name expiry* because `expiry` is native child validity, not a bridge-delivery deadline. The result includes `nativeExpiryAtOpSnapshot` as a warning, and `automaticReplayAuthorized`, `failedMessengerDeliveryProven`, `nativeRollbackProven`, `opGrantsNativeRights`, `sourceFinalityIndependentlyVerified`, `opFinalityIndependentlyVerified`, `currentNativeAuthorityVerified`, `sovereignReceipt` are **always `false`**. No `SOVEREIGN`, `LOCKED_RECORD` or G2.4 acceptance may depend on this output.

All RPC finality labels, timestamps, hashes, bytecode and ABI responses are **provider assertions**, not Ethereum beacon consensus proofs or OP fault-proof attestations; two separate chain clients are not independently verified providers. The canonical L1/OP Messenger proxies, upgrade roles, ENSv2 migration/EAC and native expiry/re-registration are out of scope. No mainnet or Sepolia broadcasts or background retry mechanism. Tests use local read-only mocked viem clients, including delayed/native-expired OP snapshots, already observed/idempotent and cancelled results, source receipt failures, mismatched result IDs, wrong domains and reorg/finality rejection.
