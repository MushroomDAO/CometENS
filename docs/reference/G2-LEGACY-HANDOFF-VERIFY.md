# G2.7/G2.8: finalized legacy ENSv1 native-handoff observations

**Read-only, non-sovereign evidence only.** `scripts/verify-legacy-native-handoff.mjs` accepts a public read client, a direct ASCII-LDH `.eth` second-level parent and one child, an expected member and resolver, three independently pinned legacy runtime codehashes, and optional *known* operator addresses for sampled approval checks. The script does not sign, broadcast, deploy, or modify any ENS contract. The live Sepolia ENS ecosystem now uses **ENSv2**, so old ENSv1 observation is not current ENSv2 member ownership.

It rejects wrong networks, missing/unpinned code, RPC errors, unfresh or missing/zero finalized L1 block hash. At **one finalized block number** it checks legacy ENS Registry parent and child pointers, NameWrapper parent/child holders, `CANNOT_UNWRAP` parent and `CANNOT_UNWRAP | PARENT_CANNOT_CONTROL` child, registrar ERC-721 custody (`BaseRegistrar.ownerOf` must be NameWrapper), true `.eth` registrar `nameExpires` excluding the 90-day grace period, parent/child expiries and a 24-hour safety margin, child resolver, and known NFT approval/upgrade pathways. It samples both NameWrapper member and Registrar Wrapper-owner `isApprovedForAll` for caller-supplied actors and examines `getApproved`, Registrar NFT approval, and Wrapper `upgradeContract`. `nativeTitleSnapshotMatches` only describes sampled owner/fuse/expiry bytes, **not safe handoff**; `knownPrivilegePathObserved` exposes tested bypasses. `memberCanSetResolverObserved` means the member appears **able** to submit a resolver change, **not** the only address capable of changing it. `memberCanTransferObserved` and `memberCanSelfExtendExpiryObserved` are conditional bitfield observations, not guaranteed actions. `nativeLegacyHandoffConditionsObserved`, `nativeHandoffSafetyObserved` and `memberResolverAutonomyObserved` are deliberately ALWAYS false because inherited and global approvals/upgrade rights are not exhaustively provable. Each read uses the same finalized `blockNumber`; the result includes `finalizedBlockHash` for reproduction, and repeats the header hash read to detect a changed block during observation. A malicious single RPC could lie consistently: this is **not** independent consensus validation.

**Hard limits:** sampled approval lists cannot enumerate *all* NameWrapper/ERC1155 operators, inherited roles, protocol governance or all upgrade privileges. Reading a single third-party RPC is not a cryptographic light-client or consensus proof. Result flags `approvalInventoryExhaustive`, `independentConsensusProofVerified`, `ensV2AuthorityVerified`, `opControllerAuthorityVerified` and `sovereignReceipt` are **always false**, even when `nativeLegacyHandoffConditionsObserved` is true. Resolver implementation/gateway/record authority, post-tx finality, member approval scope, and transfer/migration continuity still require independent security evidence. This script deliberately cannot mint a `SOVEREIGN` or `LOCKED_RECORD` receipt. G2.7–G2.9 remain PENDING until actual native ENS handoff and independent full-role verification.

No example codehash is embedded: the owner/reviewer must first verify the deployed runtime bytes from an independently trusted source and provide their exact 32-byte `keccak256` hashes, including the BaseRegistrar. Do not expose private RPC tokens in public test profiles.
