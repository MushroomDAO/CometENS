# G2.4 — L1-native atomic issuance with request-bound OP result (local fixture)

**Status:** experimental L1 Sepolia/OP Sepolia Solidity harness, **not deployed, not independently audited, and not an accepted G2.4 implementation**. This PR is stacked on [OP provisional inbox PR #157](https://github.com/MushroomDAO/CometENS/pull/157). It does not weaken the [frozen G2.4 requirement](../goal/G2-ACCEPTANCE.md) or add a platform superowner, escrow, independent OP issuance or privileged record writers.

The `G2LegacyL1NativeResultRelay` contract inherits the existing [L1-native legacy ENSv1 issuer proof](G2-L1-NATIVE-ATOMIC-ISSUE-PROOF.md) and refactors its protected native-issuance body into the internal `_issueNative` method. Both `issueNative` and the new `issueAndRelay` entrypoint apply `onlyCurrentLegacyNativeHolder`, and both invoke the same pre/post NameWrapper/Registry checks, expiry, custody, label, member ownership and CU/PCC fuses. No signature or OP queue entry alone authorizes L1 minting.

The native holder supplies exact `(label, member, resolver, expiry, opRequester, requestNonce, minGasLimit)`. Before any external call, `issueAndRelay` pins chain, original L1 source and L1 Messenger runtime, checks gas and nonce bounds, derives the native child node, and computes

`requestId = keccak256(abi.encode(VERSION, L1_CHAIN_ID, OP_CHAIN_ID, address(this), destinationInbox, parentNode, opRequester, childNode, member, expiry, requestNonce))`

which matches the OP inbox's queued-request hash. It marks this request ID as consumed before callbacks, then executes the **native L1 issuance**, validates the postconditions, and calls the configured version-pinned L1 Messenger's `sendMessage(destinationInbox, abi.encodeCall(observeResult, (result)), minGasLimit)` in the same transaction. A failed message send, native check, member callback or post-messenger parent holder change **reverts the entire L1 operation**, including the native mint, message attempt and consumed flag. OP's official Messenger is expected to authenticate this L1 contract as `xDomainMessageSender`; it may then mark an existing matching request **OBSERVED only**, never as finalized native sovereignty.

Local tests use fixed-source mock ENS Registry, NameWrapper and registrar code; a mock L1 Messenger saves the exact encoded calldata; the same Foundry process switches chain IDs to deliver that calldata via a mock OP canonical Messenger against a contract with the OP inbox's runtime/immutables. These tests establish the intended EVM transition logic **only**. They are not a live cross-chain bridge, a real ENS NameWrapper bytecode fork or an independent L1 Ethereum consensus proof. All real chain operations and deployments are excluded.

**Important recovery boundary:** if `issueAndRelay` uses a requester/nonce not queued on OP, L1 issuance can still be valid (authorized by the current native holder), while the OP message is refused. A pending OP request can also be cancelled while a native L1 tx is in flight, causing an eventual OP observation rejection without undoing native issuance. This needs an independently reconciled per-name L1 state, clear `OP_SYNC_PENDING` UX and replay/recovery design; it must not be misreported as a native rollback. The separate direct `issueNative` entrypoint remains supported and does not emit a bound OP result.

**Remaining release gates:** verify a real canonical L1 and OP Messenger deployment/codehash, actual Ethereum Sepolia ENSv1 custody and NameWrapper semantics against forked onchain bytecode; handle ENSv2 native hierarchy/EAC separately. Authenticate finalized L1 source and OP execution, receipt inclusion and per-request delivery; guard OP resolver/member-controlled records independently. A canonical OP messenger can deliver **before** its L1 source is finalized, so this inbox never considers a delivered message sufficient to satisfy G2.4 strict immediate L1 transfer revocation. The security-sensitive transition remains on L1 at execution time.
