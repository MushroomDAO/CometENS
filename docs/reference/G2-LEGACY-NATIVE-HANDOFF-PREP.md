# G2.7 — legacy ENSv1 unsigned native handoff preparation

> **Preparation only; not a native handoff receipt, current ENSv2 authorization, or an executed transaction.** This development script handles a *legacy ENSv1 on Sepolia* direct child of a single lowercase ASCII `.eth` 2LD. Sepolia's active ENS deployment is ENSv2, so using these old legacy addresses cannot prove today's ENSv2 ownership or resolution.

`scripts/prepare-legacy-ensv1-handoff.mjs` exports `prepareLegacyEnsV1Handoff(options)`. It returns an unsigned `from/to/data/value` for the legacy `NameWrapper.setSubnodeRecord(parentNode,label,member,resolver,ttl,fuses,expiry)` method, with `ttl=0` and child `PARENT_CANNOT_CONTROL | CANNOT_UNWRAP`. The intended parent owner must inspect this calldata and independently sign/broadcast with their wallet, **if they consciously choose to**, after separately verifying the official chain environment. The script contains **no signer, keys, wallet client, submit or auto-transaction operation**.

### Read preconditions

The caller supplies a public read client and all of: `parentName` (e.g. `community.eth`), child `label`, exact expected wrapped parent owner, member owner, resolver, requested `expiry` as bigint UNIX seconds, and **three independently verified deployed runtime keccak256 codehashes** (`expectedRegistryCodeHash`, `expectedWrapperCodeHash`, `expectedRegistrarCodeHash`). Unknown or malformed pins are rejected; do not guess or copy the reference examples as real hashes.

The reader requires chain ID **11155111**, a recently finalized block (number **and hash**) and bytecode at that one block for the legacy Registry `0x00000000000C2E074eC69A0dFb2997BA6C7d2e1e`, Wrapper `0x0635513f179D50A207757E05759CbD106d7dFcE8`, and `.eth` Base Registrar `0x57f1887a8bf19b14fc0df6fd9b2acc9af147ea85`. It then checks `Registry.owner(parent)==Wrapper`, actual `Wrapper.getData(parent).holder==expectedParentOwner`, parent `CANNOT_UNWRAP` burned **and `CANNOT_CREATE_SUBDOMAIN` not burned**. A `Registry.owner(child)==zero` result alone is not enough: it additionally requires that `Wrapper.getData(child)` has zero owner/fuses and its residual expiry does **not exceed the requested expiry**. NameWrapper's `_normaliseExpiry` otherwise silently raises the minted child's expiry to the old value, even if the Registry node has been released. The `.eth` BaseRegistrar NFT must actually be held by Wrapper, with no token-specific `getApproved`, and the Wrapper `upgradeContract` must be zero; otherwise prepare fails closed rather than ignoring possible Registrar `reclaim` / upgrade paths. It reads Registrar `nameExpires(labelhash(parent 2LD))`, **not merely wrapper expiry including the 90-day grace period**: registrar registration must have at least 24 hours left and the **effective** child expiry must end at least 24 hours **before** registrar expiration and not exceed wrapper expiry. Wrong network, untrusted code, grace/expiry, parent ownership or existing child fail closed. Only ASCII-LDH labels are accepted, not full ENSIP-15 normalizer support.

### What this deliberately does NOT prove

- A prepared transaction might revert or never be signed. **No child exists merely because `data` was encoded**. Ownership, PCC/CU, expiry and finality must be **re-read from actual L1 finalized chain state after execution** by an independent verifier before a name can even be considered for native handoff acceptance.
- It does not verify the member's resolver actually serves records, an EIP-1271 recipient's ERC1155 receiver compatibility, *all* unenumerable global token/operator approvals (including the parent ERC1155 `setApprovalForAll` and Registrar `isApprovedForAll`), ENS protocol-level governance/proxy/admin risk, multisig participation, or the holder's ability to sign at transaction time. The Registrar NFT custody and token-specific approval checks are necessary **but not sufficient** to prove that no third party could exercise `reclaim`. Future transaction-time state might differ from the finalized snapshot. `blockHash` is reported for independent comparison; it does not itself authenticate consensus or turn a single RPC into a proof. No `SOVEREIGN` classification may use the prepared draft.
- The generated fuse set is **PCC + CU only**, **without `CAN_EXTEND_EXPIRY` (1 << 18)**. As a result the member generally cannot extend the child name's expiry without the parent's authorized renewal action. Adding that bit is a separate, explicit handoff tradeoff that would allow the child owner to self-extend **only up to the parent expiry**; renewing the `.eth` parent does not automatically extend a child. No auto-renewal or perpetual-name claim is made. `CANNOT_SET_RESOLVER` is deliberately not burned so the member can recover from a failed resolver.
- It does not implement ENSv2 EAC registry role transfer or migration. It never changes legacy ENSv1 resolver pointers, broadcasts L1/OP writes, deploys code or publishes npm artifacts.
