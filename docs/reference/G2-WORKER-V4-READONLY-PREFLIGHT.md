# G2.6 Worker V4 signed issuance dry-run endpoint

The API Worker now exposes `POST /v4/issuance/preflight`, **disabled by default**. It is strictly a read-only OP Sepolia (`11155420`) application-NFT preflight; no source code in this route calls `sendTransaction`, `writeContract`, a nonce KV mutation, or a signer. It reuses the existing exact-contract V4 EIP-712 / ERC-1271 `eth_call` verifier and returns `preflightOnly:true`, `nativeAuthorityVerified:false`, `atomicExecutionVerified:false` even when the preflight succeeds. A later transaction must still atomically verify and consume the on-chain issuance nonce. Nothing here grants native L1 ENS rights.

To opt in on an isolated test Worker only, set trusted server configuration `NETWORK=op-sepolia`, `V4_PREFLIGHT_ENABLED=true`, `V4_PREFLIGHT_CONTRACT` (deployed V4 address), `V4_PREFLIGHT_CODEHASH` (independently pinned runtime hash), `V4_PREFLIGHT_PARENT_NODE` (parent namehash), and a valid `OP_RPC_URL`. Do **not** enable these on existing production V3 Workers without separate deployment, verification and rate limiting. If absent or mainnet, the route returns HTTP 403 before any RPC verification.

The request is JSON with exactly `operator`, `member`, `initialAddr`, `label`, `nonce` (decimal string), `deadline` (decimal string), `signature` (hex). Body limit: 8 KiB. If accepted, it returns a pinned block and application-only scope; a denial returns a sanitized code without leaking signatures, RPC URLs or provider errors. The existing V3 write endpoints still use their legacy KV nonce mechanism and are **not** upgraded to G2.6 by this addition. Full G2.6 remains PENDING until signed issuance has an audited on-chain execution path, final receipt, replay and post-transfer validation and genuine Worker V4 deployment integration.
