# G2.4 ENSv2 deployed Sepolia fork negative evidence

Verified address identity against [official ENS deployments](https://docs.ens.domains/learn/deployments/): RootRegistry `0xb458d6a3a77919449d03e7a6903c26827c1ec43f`, ETHRegistry `0xd4ebcbbdf463c9c45784603db0ddd499bc44a8b4`. ABI selectors are those of [ENSv2 PermissionedRegistry](https://docs.ens.domains/ensv2/permissioned-registry/) and [EAC](https://docs.ens.domains/ensv2/enhanced-access-control/).

Actual read-only Sepolia Anvil fork executed successfully using `https://sepolia.drpc.org` on block **11980675**. Both deployed addresses returned runtime bytecode keccak256 `0xddb7698fc2857f7a9e726491025fead241791f113a19714149db8cbf87688e98` (proxy runtime identity, **not** independently verified implementation hash). `ethereum-sepolia-rpc.publicnode.com` responded to chain-id requests but failed initial Anvil fork genesis with `block not found: 0xb6cf83`; `sepolia.drpc.org` fork worked. Both endpoints are public and require no secrets.

Reproduce with an Anvil fork using `anvil --fork-url https://sepolia.drpc.org --fork-block-number 11980675 --port 18761 --silent`, then `forge test --root contracts --fork-url http://127.0.0.1:18761 --match-contract G2Ensv2LiveSepoliaForkTest -vv`. All four tests passed against real deployed code: `.eth` current parent state, unauthorized root admin grant, unauthorized ETH root resolver role grant, and unauthorized `.eth` resolver/EAC mutation. `vm.prank` only impersonates an attacker on the local fork; zero live chain writes/signatures.

The test proves only that a randomly chosen outsider has no indicated EAC privileges at the observed block. It **does not** show current community parent ownership or member exclusivity: official deployed EAC root operators/admins, ERC1155 approvals, versioned token IDs, UUPS implementation/admin history, resolver-specific EAC permissions, expiry/re-registration, governance upgrades and pointer migration require additional analysis. No SOVEREIGN claim; G2.4/G2.9 remain pending.
