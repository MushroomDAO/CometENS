# G2.4 — second-provider finalized-RPC block corroboration (read-only)

**Status:** offline/read-only observational guard, not real consensus verification or G2.4 acceptance. This is an optional conservative follow-up to the [historical L1/OP result reconciler](G2-NATIVE-CROSSCHAIN-RESULT-RECONCILE.md). Do not use its output to mint native ENS subdomains, authorize OP resolver writes, declare member sovereignty, or replace L1 execution-time authority checks.

The pure-client module `scripts/corroborate-g2-native-result.mjs` exposes `reconcileWithSecondProviders({l1Client,opClient,secondaryL1,secondaryOp,profile})`. First it runs the existing source-backed `reconcileNativeIssueResult` on the primary L1/OP clients, requiring native L1 issuer/result and OP inbox historical correlation. Then it passes that *strictly non-sovereign* observation to `corroborateNativeResultBlocks({observation,secondaryL1,secondaryOp})`.

Each secondary provider must report the expected chain ID (11155111 Ethereum Sepolia or 11155420 OP Sepolia), a recent `finalized` head **at or beyond** the historical transaction block, and the identical block hash at the historical block number. The checker reads its finalized head, then numbered block, then finalized head and numbered block **again**. A conflicting historical hash, nonexistent numbered block, finalized rollback, changed hash at the same finalized height, wrong chain, stale or future source timestamp, malformed observation, or RPC error fails closed with a sanitized reason code.

Two clients are required per chain (the primary and secondary cannot be the same JavaScript object), but **this cannot verify that their endpoint operators, upstream nodes, infrastructure, or consensus source are actually independent**. Separate clients pointed at the same RPC service can agree while reporting the same lie. The provider's `finalized` tag is not an Ethereum beacon-chain or rollup state-root proof. For OP, a provider's historical block confirmation does not independently establish the canonical L1 finalization of the OP output root or valid fraud-proof/challenge assumptions. The secondary check only corroborates **block-number / block-hash agreement**.

On positive agreement the status is `TWO_RPC_PROVIDER_BLOCK_HASH_AGREEMENT`, evidence level `SECONDARY_FINALIZED_RPC_HEADER_AGREEMENT_ONLY`, and `historicalObservationsCorroborated: true`. Critically `providerIndependenceVerified`, `ethereumConsensusIndependentlyVerified`, `nativeCurrentAuthorityVerified`, `finalizedL1IssuanceVerifiedOnOP`, `opGrantsNativeRights` and `sovereignReceipt` all remain **false**. A historical successful L1 issuance may have been followed by an actual parent transfer, expiry or resolver migration; this module does not independently verify any current rights.

No credential-bearing URL is placed in returned data/errors. Secondary RPC errors are sanitized; no network requests are made by the test fixtures (all use mocked read-only clients). This PR introduces no signer, canonical Messenger delivery, request state mutation, ENSv2 authority assertion, chain transaction or deployment.
