# G2.4 native issuance: actual Sepolia ENSv2 fork gate

This branch copies the experimental #171 `G2Ensv2AtomicSubnameProof` contract and its existing unit tests into a new isolated branch from `origin/main c594057` (because #171 remains open), then adds actual deployed-runtime negative tests. No changes to #171 or #177 worktrees.

Official [ENSv2 Sepolia deployments](https://docs.ens.domains/learn/deployments/): RootRegistry `0xb458d6a3a77919449d03e7a6903c26827c1ec43f`, ETHRegistry `0xd4ebcbbdf463c9c45784603db0ddd499bc44a8b4`. Fork via `anvil --fork-url https://sepolia.drpc.org --fork-block-number 11980675 --port 18762 --silent`; run `forge test --root contracts --fork-url http://127.0.0.1:18762 --match-contract G2Ensv2NativeActualForkTest -vv`. Four tests pass against the actual ENSv2 runtime with no `vm.etch`, simulated registry or mainnet write.

The real fork establishes a **specific blocking prerequisite**: a newly instantiated gate has no child ETHRegistry root registrar permission, even when called by the live RootRegistry `eth` registration's holder. Outsiders fail the gate as expected; parent expiry also fails, and an outsider cannot replace the `eth` subregistry pointer. These do not demonstrate successful member issuance, genuine transfer/re-registration by an authorized parent, or absence of other privileged EAC actors. The migration and re-registration test only verifies rejection of an *unauthorized attempt* and unchanged pointer, not a successful authorized migration. Additional tests need a controlled named parent registry or a vetted official registrar grant path on a local fork, with EAC roles and proxy upgrade governance independently pinned. The runtime proxy codehash alone does not authenticate implementation provenance. No exclusive sovereignty asserted; G2.4 remains pending.
