# G2.9 — Opt-in legacy ENSv1 member record bundle lock (partial)

> **Prototype only, local Foundry tests, NOT deployed or user-accepted.** This is a one-time immutable record *bundle* for one legacy ENSv1 `.eth` subname, **not proof that the live ENS Registry resolver pointer is immutable**, not a current Sepolia ENSv2 EAC resolver, and not a complete `LOCKED_RECORD` or `SOVEREIGN` receipt. G2.9 remains `PENDING`.

`contracts/src/G2LegacyMemberRecordLock.sol` is a separate non-upgradeable, single-name record-store/resolver-like contract. Constructor pins its parent label and direct child label to ASCII-LDH, the **correct** `namehash('eth')`, Ethereum Sepolia chainId `11155111`, official *legacy* ENS Registry/NameWrapper/BaseRegistrar addresses, and three independently verified deployed runtime hashes. Neither constructor nor deployment locks ENS records.

The current native NameWrapper **member** may call `lock(addr,contenthash,key,value)` **exactly once**, after contract codehash checks and live L1 reads confirm Registry points parent and child to the official Wrapper, BaseRegistrar owns parent's `.eth` ERC721 in Wrapper custody, current member equals `Wrapper.getData(child).holder`, parent CU and child PCC|CU burned, parent/child expiry safely in the future, and `BaseRegistrar.nameExpires` has more than 24h remaining *excluding its grace period*. User must voluntarily inspect their exact values. The call stores a single ETH address, one contenthash, and one `(textKey,textValue)` pair, emits the `MemberRecordsLocked` event with `recordCommitment=keccak256(abi.encode(node,addr,contenthash,key,value))`, and sets `locked=true`. From then on **this contract has no record-edit, owner, admin, upgrade, delegatecall, proxy, emergency-recovery or unlock function**; even its former member cannot replace the locked bundle.

The contract exposes `addr(bytes32)`, `text(bytes32,string)` (one locked key only), and `contenthash(bytes32)` readers. It is not a complete ENS UniversalResolver/ENSIP-10 implementation and is not automatically installed as `Registry.resolver(name)`. No automatic NameWrapper.setResolver transaction is included. Locking this data and *then* pointing the ENS resolver elsewhere may render the immutable bundle irrelevant to actual ENS resolution. Other name-related roles, migration, underlying NameWrapper upgrades, operator approvals and parent expiry may still allow a protocol controller or member to redirect actual resolver routing, lose the name, or break resolution. We always return `sovereignReceipt=false`, `ensV2AuthorityVerified=false`, `nativeResolverPointerLockedVerified=false`. To ever assert `LOCKED_RECORD`, a third-party verifier must separately prove the active L1 resolver pointer cannot change under **all** surviving parent/admin/approval/upgrade/ENSv2 EAC pathways and that the deployed resolver serves these precise records at a finalized block. None of that is claimed here.

**Recovery tradeoff:** this one-time lock is deliberately irreversible. If a member signs wrong ETH address, contenthash, key/value, or the gateway referenced by a record goes offline, there is no setter to repair the bundle. The user can create another contract, but the old bundle remains unchanged and moving the ENS pointer elsewhere may require name permissions (or be impossible after fuse locks). Expired/renewed/re-registered `.eth` names do not automatically transfer this bundle's control and the old records may become semantically stale. This opt-in requires a **separate explicit member wallet transaction**; development/tests never execute public-chain writes.

Current test evidence covers: independent pre-pinned `community.eth/alice.community.eth` namehash vectors, nonmember/platform denial, wrong fuse/custody/wrapped holder, expiry/grace, wrong chain/runtime codehash, invalid record sizes, immutable response after lock and inability of anyone to overwrite. It is only a building block for the full [G2 acceptance](../goal/G2-ACCEPTANCE.md) alongside [native legacy handoff verifier](G2-LEGACY-HANDOFF-VERIFY.md) and separate ENSv2 authority analysis.
