# research — 立项依据与开源全景

## 我们到底在做什么产品

CometENS 是一个 **Apache 2.0 开源的社区 ENS 域名管理工具**。任何人都可以拿去部署,
用来管理**自己社区的 .eth 域名**并向成员分发二级域名。

核心用户旅程(产品的最小闭环,其余都是增量):

```
社区拥有一级域名        aastar.eth        ← 归社区
   ↓ 用户 jack 加入社区
自动获赠二级域名        jack.aastar.eth   ← 归 jack 本人(ERC-721,可转让)
   ↓
全网可解析              viem.getEnsAddress('jack.aastar.eth') → jack 的钱包地址
```

这不是"又一个 ENS 注册器"。差异在于:**一级域名的所有权与管理权可以分离**,
因此同一套代码支持两种完全不同的运营形态(见 acceptance.md 的模式 A/B)。

## 为什么值得做

1. **社区注册即身份**。社区拉新时除了给一个钱包地址,还能给一个人类可读的名字。
   名字归用户,社区跑路了名字还在(NFT 在用户手里)。
2. **ENS 官方没有覆盖这一层**。ENS 提供根域名注册,不提供"社区如何低成本地
   向成千上万成员分发子域并托管解析"。子域上 L1 每个都要 gas,不可行。
3. **L2 + CCIP-Read 让分发成本趋近于零**。记录写在 Optimism,解析走 EIP-3668,
   L1 只需要一次 setResolver。

## 开源全景与差异化

| 方案 | 定位 | 与我们的差别 |
|---|---|---|
| ENS 官方 App | 根域名注册/管理 | 不解决社区批量分发子域 |
| Durin (NameStone) | L2 子域发行 | 闭源托管为主,自部署路径弱 |
| NameStone / Namespace API | SaaS 子域 API | 闭源,数据与密钥在厂商侧 |
| **CometENS** | **可自部署的开源社区域名工具** | **自部署 + 委托托管双模式;管理权可撤销** |

我们的位置:**给不想把域名主权交给 SaaS、又没有能力从零造轮子的社区**,
一套能自己跑起来的开源件。
