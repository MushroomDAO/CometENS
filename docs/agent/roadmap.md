# roadmap — Milestone → Feature 规划

> 本文件是 pilot 的规划层。仓库里原有的 `docs/roadmap.md` 记录的是**技术里程碑 A–E**
> 的历史(且停留在 v0.6.0),两者不冲突:那份是"技术做到哪",这份是"产品要去哪"。
> 同步 `docs/roadmap.md` 本身是 T1.4.1。

## 当前定位判断(2026-09-03)

**技术内核接近生产就绪,产品化没到。**

| 维度 | 状态 | 依据 |
|---|---|---|
| 合约与解析链路 | ✅ 就绪 | 198 Foundry 测试全绿;HybridResolver 测试网 E2E 通过 |
| 二级域名归用户 | ✅ 就绪 | ERC-721 mint 给 newOwner,可转让 |
| 委托管理链上原语 | ✅ 已存在 | registrar + quota + expiry,已有测试 |
| 多根域名 | 🟡 半成品 | 配置驱动已具备,端到端流程与文档缺失 |
| **自部署路径** | ❌ **缺失** | 全仓库搜不到任何 self-host 指南;脚本分散未成路径 |
| **委托托管流程** | ❌ **缺失** | 链上能力有,但无 CLI 流程、无文档、撤销未验证 |
| **界面产品度** | ❌ **demo 级** | 无共享样式表,各页内联 7/36/73 行 style |
| 主网 | ⏸ 本阶段不做 | 用户 2026-09 确认:当前只提供测试网 |

结论:**v0.7.0 = 技术验证完成的测试网服务;距离"任何社区能拿去用的标准服务"
还差一个完整的产品化里程碑,即 M1。**

## M1 — 产品化:可被任何社区自部署的标准服务(测试网)✅ **已发布 v0.8.0(2026-09-04)**

> **发布 ≠ 全部验收通过。** M1 的代码侧判据全部成立,而验收清单上仍有两条未决:
> **A3**(陌生开发者照文档 2 小时跑通)和 **B2**(撤销可验证)。
> 前者需要**一个没参与过这个仓库的人** —— 不是工程量,再跑多少次判据都不会解除;
> 后者需要域名持有者的 L1 私钥。详见 `progress.md` 与 `acceptance.md`。
>
> 之所以在这两条未决时就发布:它们**都不能靠继续开发解除**,而已完成的部分对
> 「一个社区能不能拿去用」是有价值的。把它压在未发布状态,只会让那份价值等一个
> 与它无关的事件。

目标:一个陌生开发者能自己部署一套管自己的域名;一个没技术的社区能把管理权委托给我们;
主干页面看起来像产品。**全部在测试网验收。**

| Feature | 内容 | 为什么是它 |
|---|---|---|
| **F1.1 主干流程 UI 产品化** | 设计系统 + 落地页/公开查询页/管理控制台重做(**不做登录**) | 用户直接要求;demo 观感是产品化最大短板 |
| **F1.2 自部署路径** | preflight + bootstrap + SELF-HOSTING.md | "任何人可部署"是开源定位的第一要义,当前完全缺失 |
| **F1.3 委托托管闭环** | delegate CLI + 撤销验证 + 文档 | 模式 B 的可用性;链上原语已有,差流程 |
| **F1.4 文档与规划一致性** | 同步 roadmap / 重写 README | 对外第一印象;当前 README 与 roadmap 与真实状态脱节 |

## M2 — 主网上线(推迟)

Ethereum mainnet + OP mainnet 部署、owner 切多签、密钥轮换(D5)、监控与限流(D7)。
**明确不在本轮。** 前置:M1 全部验收通过 + 主网参数评审。

## M3 — Web2 域名桥接(增量)

DNSSEC → ENS 导入、`alice.mushroom.cv` 双解析(DNS 出网页 / ENS 出钱包)、
社区与个人两层身份主页。已有文档:`docs/DNS-DOMAIN-INTEGRATION.md`、
`docs/IDENTITY-PAGES-PLAN.md`、`docs/DNSSEC-VERIFY-RUNBOOK.md`。
前置:DNSSEC 验证门通过(等用户在域名注册商侧操作)。
